# AGENTS.md

- `splitcore/` is the pure logic layer. Keep it browser-free and importable under both CPython and MicroPython.
- Preserve exact penny conservation: every split path must sum exactly to `amount_cents`.
- Money stays as integer cents; formatting belongs in `ui.py`, not here.
- `model.py` is the persisted-state trust boundary. Harden malformed saved data here rather than making the UI or calc layer compensate later.
- Keep `MODE_EQUAL` and `MODE_UNEVEN` literal values stable; tests lock persisted JSON to those exact strings.
- Do not switch `model.py` to dataclasses.
- `AppState.from_dict()` is the persisted/untrusted-state normalization path. Direct `Person`, `Item`, and `AppState` constructors do not enforce referential integrity, so do not pass browser/persisted input to them without equivalent validation.
- Person and item IDs are logical keys: keep them non-empty, bounded, unique, and free of NUL. Duplicate IDs collapse dictionary-backed shares and make UI removal affect multiple records. MicroPython's `jsffi` cuts a `str` at its first NUL when it reaches JS, so the DOM would hold a different (or another person's) id than the model and the UI would record shares for nobody or the wrong person; `_normalize_id()` rejects NUL for person, item, payer and participant ids alike.
- Bound digit counts before `parse_cents()` calls `int()`; a later `MAX_CENTS` comparison does not prevent oversized conversion failures.
- After edits here, run `python -m unittest discover -s tests` and `python -m py_compile splitcore/*.py`.
- Persisted-state hardening caps amounts (`MAX_CENTS`) and uneven weights (`MAX_WEIGHT`), both in `model.py`; `split_item()` caps weights again, `Item.from_dict()` caps them to `-MAX_WEIGHT`..`MAX_WEIGHT`, and `ui.py` shows capped weights and rejects typed ones above the cap. The cap is one issue per item only when `report_caps=True`, which backup import passes: the previous release saved typed weights above the cap, so `storage.load()` must not call such a bill malformed (the recovery warning and its `bunnysplit:corrupt` copy would never clear). Preserve those bounds and exact penny conservation when changing split math or deserialization.
- `Item.from_dict()` keeps only `mode` (and `weights` for uneven splits) in `split`, only weights for the item's own participants, and only finite `int`/`float` weights (not `bool`); strings, `null`, booleans, non-finite numbers and containers are dropped with an issue, and keys for non-participants with one issue per item. `split_item()` never reads those keys and the UI never writes them, but they were saved and parsed on every load: building one big dict is superlinear under MicroPython, and 40,000 of them made each page load take ~12 s. `1e309` parses to `inf`, and `json.dumps` writes it back as a bare `inf`/`Infinity` that the next `json.loads` rejects, losing the whole bill. The app only ever saves float weights; an imported long digit-string weight froze every render, because MicroPython's `int()` of it is quadratic, and so did 20,000 weights near `1e308` (each one showed as a 309-digit bigint) before weights were capped at `MAX_WEIGHT`. Weights below `-MAX_WEIGHT` are capped too (other negatives are kept; `split_item()` treats every negative as 0): MicroPython's `json.dumps` writes 16 significant digits, so `-1.7976931348623157e308` was saved as `-1.797693134862316e+308`, past the largest float, and the next load read `-inf`.
- Never `str()` a container from untrusted JSON: under MicroPython on wasm, `str()` of a deeply nested list overflows the JS stack with a `RangeError` that no Python `except` catches. A person whose name is a list or object is skipped; such an item description is blanked and the item kept. Report an issue whenever a field that affects money or the roster is sanitized or defaulted (a missing `amount_cents` included): backup import only warns before replacing a bill when issues are reported. Import sends users to the browser console for details, so each console line names its record (id, and name or description) and says `fixed` when the record was kept with a change (pass `kept=True` to `_report_issue()`) and `skipped` only when it was left out.
