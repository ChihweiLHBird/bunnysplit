# AGENTS.md

## Fast Start

- `bunnysplit` is a static PyScript + MicroPython app. There is no backend, no app bundler, and no hand-written app JavaScript except `sw.js`.
- Start with executable sources of truth: `.github/workflows/ci.yml`, `.github/workflows/test.yml`, `.github/workflows/deploy.yml`, `tests/`, `scripts/stage-assets.sh`, `pyscript.toml`, and `infra/__main__.py`.
- `CLAUDE.md` is a symlink to this file; edit `AGENTS.md` and do not replace the symlink with an independent copy.
- Files under `docs/superpowers/specs/` and dated review reports are historical snapshots. Use current code, tests, and workflows when they disagree.

## Instruction Maintenance

- Repository behavior is the source of truth. If an agent finds that an `AGENTS.md` statement contradicts the code, tests, workflows, or deploy configuration, patch the nearest applicable `AGENTS.md` in the same change instead of preserving stale guidance.
- Every `AGENTS.md` in this repo has a matching `CLAUDE.md` symlink; preserve those links when changing instructions.

## Boundaries That Matter

- `main.py` only boots from persisted state: `ui.start(storage.load(), storage)`.
- Keep browser-only code in `ui.py` and `storage.py`. `splitcore/` must stay importable under plain CPython and under PyScript's MicroPython runtime.
- `pyscript.toml` is the import allowlist for MicroPython files copied into the virtual FS. If you add a runtime-imported Python module, update `pyscript.toml` or the browser build will fail even if local CPython tests pass.
- `dist/` is generated by `./scripts/stage-assets.sh`. Do not hand-edit `dist/`; edit source files and restage.
- `scripts/stage-assets.sh` ships only its explicit asset manifest. Add every new browser/runtime asset there and extend `tests/test_stage_assets.py`; unlisted working-tree files must never reach `dist/`.
- Deploys are Pulumi-only from `infra/`; `pulumi up` uploads `../dist` to a Cloudflare assets-only Worker. There is no wrangler flow.
- Staging derives `dist/sw.js`'s `CACHE_VERSION` deterministically from the exact staged shell, both locally and in CI. Do not add a separate workflow-only cache stamp.

## Repo-Specific Conventions

- Money is integer cents everywhere. Do not store amounts as floats or introduce float rounding into settlement logic.
- Keep `splitcore/model.py` on plain classes, not dataclasses, to preserve CPython/MicroPython behavior.
- In `ui.py`, build user-visible DOM with `createElement` plus `textContent`; avoid `innerHTML` for any user-controlled content.
- UI rerenders create JS proxies via `create_proxy`; if you add render-time handlers, keep them tracked in `_render_proxies` so rerenders do not leak proxies.
- `storage.load()` treats `localStorage` errors and corrupt JSON as recoverable and preserves bad payloads under the `bunnysplit:corrupt` key prefix; keep that behavior instead of failing startup.
- This project is PyScript-first and intentionally minimizes JavaScript. Implement application, domain, storage, and UI logic in Python/PyScript whenever possible. Hand-written JavaScript is acceptable only for browser platform entry points that require it and have no PyScript equivalent.
- `sw.js` is the current unavoidable JavaScript exception and must remain cache plumbing only. Do not move application logic into it or add other JavaScript modules for logic PyScript can implement.

## Validation

- App or core logic: `python -m unittest discover -s tests`
- Syntax parity with CI: `python -m py_compile main.py ui.py storage.py splitcore/*.py` and `python -m py_compile infra/__main__.py`
- Service-worker and staging: `node --check sw.js`, `node --test tests/test_sw.mjs`, and `bash -n scripts/stage-assets.sh`
- Manual browser check: `python3 -m http.server`
- Before any deploy or deploy-related verification: `./scripts/stage-assets.sh`

## Hotspots

- Before changing `splitcore/calc.py` or `splitcore/model.py`: persisted-state hardening must never lose pennies or crash on malformed/oversized saved data. Amounts and uneven weights are capped at the model/calc boundary (`MAX_CENTS`, `MAX_WEIGHT`); collection shapes and unique, bounded person/item IDs are part of the same trust boundary.
- `parse_cents()` must reject excessive digit counts before calling `int()`; checking `MAX_CENTS` afterward is too late to bound conversion cost or exceptions.
- JSON backup import (`storage.parse_backup()` and the `ui.py` import handlers) is the same trust boundary as saved state: bound size before reading or parsing (`MAX_BACKUP_BYTES`, also in UTF-8 bytes of the decoded text: `Blob.text()` turns each invalid byte into a three-byte U+FFFD), reject `\u` escapes without four hex digits, unquoted digit runs longer than `MAX_NUMBER_DIGITS`, objects with more than `MAX_OBJECT_MEMBERS` members, more than `MAX_CONTAINERS` objects and lists, and any other character outside strings that `json.loads()` would reject, all before `json.loads()` (MicroPython reads the four characters after `\u` unchecked, which could hide a quote from the digit scan, converts huge integer literals in quadratic time, and builds an object whose keys share its 16-bit str hash in quadratic time; its `json.loads()` also reads `,` and `:` as whitespace, lets `]` close `{` and takes any value as a key, so members are counted as values, not colons), decode escaped surrogate pairs before `json.loads()` (MicroPython decodes each half alone into a lone surrogate that the browser shows and saves as U+FFFD), reject anything that is not an object with `people` and `items` lists before `AppState.from_dict()` (which reads missing keys as an empty bill), enforce the model's `MAX_PEOPLE`, `MAX_ITEMS`, and `MAX_PARTICIPANT_REFS` on the raw lists and `MAX_PEOPLE` on each item's raw participant list and weights (a set of ids that share a hash is quadratic to build), run `storage.check_restorable()` on the built state (name/description caps and the exact UTF-8 export size, reported as the restored size since the app's format can be larger than a minified file), and confirm before replacing a non-empty bill. Save an imported bill before assigning it to `ui._state`, with the failure message already showing, and end the file-read promise chain with a `.catch`. The UI add handlers enforce the same counts and caps on the new record and check the export size before saving, so every bill the app can build can be restored; change them together. Bills saved before a limit existed must still load and grow; only export flags them, and `storage.load()` must not report them as malformed (`Item.from_dict()` reports its weight cap only when import passes `report_caps=True`).
- MicroPython's `jsffi` in the pinned runtime (MicroPython 1.24.0) truncates JS numbers to int32, so a 4 GiB + 5 B `File.size` arrives as `5`, and cuts a Python `str` at its first NUL when it passes to JS (the model rejects NUL in ids for this reason). Never rely on a JS-reported size or count alone for a safety bound; also enforce it in JS space (for example `Blob.slice()` before reading). A JS exception raised while Python runs (for example `QuotaExceededError` from `localStorage.setItem`, or a `RangeError` when deep C recursion in wasm overflows the JS stack) unwinds through Python frames without running `except` or `finally`, so order state changes to stay consistent if one escapes. `str()` of a JS object is only `<JsProxy n>`; pass it to `console.warn` as its own argument. A Python exception passed to JS is an opaque proxy instead, so log that one as `str(e)`.
- Measure performance bounds on the pinned MicroPython runtime, not CPython: under MicroPython 1.24.0, parsing one long JSON string is quadratic (1 MiB took ~1.25 s), `json.dumps` is quadratic in output size (1.28 MiB took ~3 s, and `save()` runs it on every edit), and `settle_up()` is quadratic in people, while CPython hides all three. Render cost also scales with repeated text (names appear in every item row). Its `re` accepts `{n}` counted repetition but never matches it; spell repetitions out. Its `re` also recurses once per character on `*` and `+`, so a run of ~10,000 overflows the JS stack: never apply an unbounded repetition to untrusted text (use `str` methods or single-character patterns). Its `re.sub` also processes backslashes in what a replacement function returns. Its `str` hash is 16 bits and its dicts and sets probe linearly, so a dict or set built from untrusted keys must be small.
- Before changing `index.html` or `sw.js`: offline cold boot depends on the PyScript runtime being cached as a CORS-usable response, not opaque. Keep runtime warmup in default (cors) fetch mode, keep required app-shell installation atomic, and keep cache writes inside the fetch event lifetime. During a service-worker update, new `.py` files can run under the cached previous `index.html`, so `start()` must skip elements the previous shell lacks (as it does for the Backup panel) rather than crash before rendering.
- `index.html` enforces a Content-Security-Policy `<meta>` (first in `<head>`) that allows only the pinned PyScript release path, the MicroPython build PyScript imports from jsDelivr, Google Fonts, and this origin. When bumping PyScript, update both CDN paths in the policy and `PYSCRIPT_MICROPYTHON` in `tests/test_csp.py`, then load the app and confirm the console shows no CSP violations. Keep the page free of inline scripts, inline styles, `style` attributes and `eval`; from `ui.py`, style through `element.style`, never `setAttribute("style", ...)`.
- Save-status UI (`index.html`, `styles.css`, `ui.py`): the save-failure warning must never be color-only and must surface on mobile and at startup (`start()` probes `storage.writable()` and the `.err` label stays visible on narrow screens).
- Official actions and actions from reputable vendors (for example `actions/*`, `docker/*`, and `pulumi/actions`) are trusted; do not flag their maintained release tags without independent evidence of a concrete risk. Scrutinize unknown publishers and suspicious provenance.
- The version-pinned PyScript runtime served by the official `pyscript.net` CDN is trusted; do not report CDN delivery alone without independent evidence of compromise or another concrete risk.
